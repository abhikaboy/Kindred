# Kindred Activity & Personalization: Handoff

A snapshot of where Kindred's insights / personalization feature stands, what data exists, and the open questions. Written so someone with no access to the codebase can reason about what to build next.

## 1. Product context

**Kindred** is a social productivity app. Users keep tasks in **workspaces** (each with **categories**), and friends can see each other's progress.

- **Kudos:** friends send encouragement ("cheer on" an in-progress task) or congratulations (on a completed task). Kudos can be text, images/GIFs, or video, and the receiver can react.
- **Activity rings:** three daily rings, **Plan**, **Do**, and **Share**, plus a streak of days the rings were closed.
- **Recurring tasks / habits:** tasks with a rhythm (daily, weekly, and so on).
- **Platforms:** iOS/Android app (React Native) and a desktop app (React + Tauri), backed by one Go API on MongoDB.

**Goal of this feature:** help users understand themselves ("what we noticed about you") in ways that actually change behavior. Today's page reads as an overwhelming dashboard that shows data without insight.

## 2. Design constraints (from Kindred's design guide)

Any proposal has to fit these:

- **One headline per screen**, light supporting text, and at most two or three text styles.
- **No nested cards, no uppercase eyebrow labels, no filler subtitles.** A caption is only allowed when it carries live information (a count, a status, an insight).
- **No loud status pills.** Status goes inline in caption color: "· Slipping".
- **No emojis anywhere in UI copy.**
- **One purple (primary) call to action per screen.**
- **Reveal one helper at a time**, never everything at once.
- **Quiet motion:** short fades, no springs or staggered cascades.
- **Desktop mirrors mobile's structure.** No desktop-only redesigns.
- **Copy:** short, plain, sentence case, no marketing voice.
- **"Suggested for you" must say why.**

## 3. The data: one endpoint

`GET /v1/user/analytics?range=week|month|sixmonth&workspace=<name>&category=<id>`

Returns one widget-ready payload; the client does no computation. Many sections include a **`takeaway`**, a plain-language sentence generated by the backend from templates. Field shapes:

```ts
AnalyticsResponse {
  range: "week" | "month" | "sixmonth"
  generatedAt: string
  workspaceFilter?: string
  categoryFilter?: string

  // Headline stats, each vs the previous period
  signals: { momentum: Signal; timing: Signal; support: Signal }
  //   Signal { label, value (display string), rawValue, delta, deltaLabel, direction: "up"|"down"|"flat" }

  // Completions over time, stacked by category
  progress: {
    total, prevTotal, delta (percent), bucketUnit, takeaway,
    buckets: { date, label, total, segments: { categoryId, name, color, count }[] }[],
    legend: { categoryId, name, color }[]
  }

  // Where effort went
  categoryShare: {
    takeaway,
    slices: { categoryId, name, color, count, pct }[],
    overTime: { label, slices: Slice[] }[]
  }

  // GitHub-style daily completion heatmap
  heatmap: { total, maxCount, takeaway, days: { date, count, level }[] }

  // Recurring-task consistency
  habits: {
    takeaway,
    rows: { templateId, title, frequency, rhythmLabel, completed, total,
            dots: boolean[], status, nextDueAt? }[]
  }

  // Per-category and per-workspace health
  categoryHealth:  { rows: { categoryId, name, color, workspace, done, onTimePct, kudos, sparkline: number[], status }[] }
  workspaceHealth: { rows: { workspace, done, onTimePct, kudos, status }[] }
  //   status is one of: healthy | steady | needs-attention | needs-reset | slipping | unsupported | light

  // When the user finishes things (weekday is Monday-indexed: 0 = Mon … 6 = Sun)
  bestTime: { takeaway, maxCount, cells: { weekday, hour, count, level }[] }

  // Tasks that have stalled or slipped
  attention: { tasks: { id, title, workspace, category, categoryId, daysOpen, deadline?, reasons: string[] }[] }

  // Median time-to-done for tasks with vs without kudos. Intentionally non-causal;
  // hasComparison gates the comparison copy when there isn't enough data.
  kudosEffect: { hasComparison, withKudosMedianHours, withoutKudosMedianHours, withCount, withoutCount, takeaway }

  // How much of the user's work got any support
  supportCoverage: { pct, supported, total, takeaway }

  // Who supports the user most
  topSupporters: { id, name, icon, count }[]
}
```

Related data that exists elsewhere in the API (not in this payload):

- **Rings today:** Plan/Do/Share progress, closed state, current streak.
- **Received and sent kudos:** sender, message, task, timestamp, read state, reaction.
- **Tasks:** created, start, deadline, and completion times; priority; recurrence; and "working on since" (when a user starts a task).

## 4. Current state of the Activity page (desktop)

Just redesigned into **three views**, chosen with a switcher under the "Activity" title. A week/month/6-month range control and a workspace filter sit at the top right.

| View | Question it answers | Sections |
|---|---|---|
| **Overview** | How am I doing? | Signals (3 stats with change vs last period), Needs attention (stalled/overdue tasks, each linking to the task), Progress chart |
| **Patterns** | When and what do I get done? | Best-time grid (weekday by 3-hour block), daily heatmap, category share, habits |
| **Together** | Does support help? | Kudos effect (with vs without bars), support coverage plus top supporters (linked to profiles), workspace and category health |

Each section shows its title, then the backend's takeaway sentence, then the chart or list. Status labels are inline text, not pills.

Also new: the **desktop home screen's card stack** now opens with the user's recent unread kudos (from the last 3 days, up to 3) before their tasks.

**Before this redesign,** the page showed seven widgets on one scroll and ignored five parts of the payload: `bestTime`, `attention`, `kudosEffect`, `supportCoverage`, `topSupporters`.

## 5. Known gaps and limitations

- **Takeaways come from templates.** They describe ("You completed 23 tasks") more than they notice ("You skip gym tasks scheduled after 6pm"). Richer observations need new backend analysis.
- **Insights don't lead to actions.** Nothing says "move this task to your peak time" or "ask a friend to cheer this on."
- **Insights aren't used anywhere else.** For example, the home stack isn't ordered by the user's best time, and quick-add doesn't default to peak hours.
- **No recap ritual.** There's no weekly or yearly summary moment and nothing shareable.
- **Health statuses can feel like a report card** and may not lead to decisions.
- **The 6-month range and the category filter** are probably rarely used (not verified with analytics).
- **The mobile app** has its own analytics screens; whether they match desktop hasn't been audited yet.

## 6. Ideas on the table (not decided)

- **"Your week" recap:** a short Spotify Wrapped–style card sequence every Sunday, about six cards: the week in one line, peak time, longest-kept habit, who showed up for you, what slipped plus one suggestion, and a shareable summary card. Could also run monthly and yearly.
- **"We noticed" insight cards:** one observation at a time, each with a reason and one action button.
- **Quiet personalization:** use insights inside existing flows (home ordering, default times, nudge timing) instead of on a separate page.
- **Possible cuts:** pie/category share, health scores, the 6-month range, comparisons against other users.

## 8. Research findings

### Evidence on what changes behavior

Caveat: the evidence that self-monitoring helps is strong. The evidence for specific chart types is weak or missing. Company metrics come from press releases, not replicated studies.

**Principles, strongest evidence first:**

1. **Monitoring works best when someone else sees it.** Meta-analysis of 138 RCTs (N≈20k): monitoring progress improves goal attainment (d=0.40). The effect was larger when progress was reported to another person (d=0.47) than when kept private (d=0.19); the public subgroup is small. Progress also has to be recorded, not just noticed. [Harkin et al. 2016](https://eprints.whiterose.ac.uk/91437/). This directly supports Kindred's Share ring.
2. **Social mechanics work, but support-only groups can backfire.** In an RCT (n=790), competitive networks raised class attendance about 90% vs control, while support-only teams did *worse* than control because they made inactive members visible. [Zhang/Centola 2016](https://pmc.ncbi.nlm.nih.gov/articles/PMC5008041/). In STEP UP (n=602), only the competition arm kept its effect after the program ended. [Penn](https://penntoday.upenn.edu/news/competition-works-better-support-or-collaboration-increase-daily-step-counts). Implication: kudos alone may not be enough. Light, friendly comparison ("you and 3 friends all closed Plan today") is better supported.
3. **Streaks motivate, but breaks hurt, so build in repair.** Seeing an intact vs broken streak changed re-engagement (66% vs 58%) for identical behavior; the drop was smaller when people could repair the streak. [Silverman & Barasch 2023](https://knowledge.insead.edu/marketing/consumer-streaks-are-motivating-key-keeping-them-alive). Duolingo (company data, not peer-reviewed): separating the daily goal from the streak gave +3.3% day-14 retention [blog](https://blog.duolingo.com/improving-the-streak); Streak Freeze reportedly gave about +10% long-term retention (second-hand report).
4. **Data must lead to an action, or people drop it.** Problems early in tracking carry forward and block reflection and action [Li, Dey & Forlizzi 2010](https://courses.cs.washington.edu/courses/cse440/15au/readings/PersonalInformatics-Li2010.pdf). People abandon trackers because collecting data is a hassle, they dislike what it shows, they don't know what to do with it, or they learned what they needed; guilt is common after quitting [UW](https://www.washington.edu/news/2016/09/08/life-after-fitbit-appealing-to-those-who-feel-guilty-vs-free/).
5. **Recaps drive sharing and acquisition; retention impact is unproven.** Spotify Wrapped 2020: 90M+ users engaged, 60M+ shares, +21% app downloads in early December (press-sourced). None of these figures measure behavior change.

**Our candidate insights, ranked by evidence:**
- Strong: habit consistency and streaks with repair; weekly totals vs your own past; stalled tasks with a one-tap next action.
- Moderate: top supporters and the kudos effect. Social accountability has support, but nothing directly shows that displaying the effect of encouragement changes behavior. It is also a correlation, so the wording must not imply cause.
- Weak: best time of day/week, category share, activity heatmap. They describe; no outcome studies found.
- Wrapped-style recap: good for sharing and growth; anecdotal as a retention tool.

**Pacing:**
- **Daily:** rings and streaks only.
- **Weekly:** the main insight moment, with 1–3 takeaways each tied to an action. This is inferred from the evidence; no study compares weekly vs monthly directly.
- **Yearly or seasonal:** one shareable recap, possibly timed to fresh-start dates like New Year (Dai, Milkman & Riis 2014; not verified in this pass).

**What not to build:**
- Hard streak resets with no freeze or repair.
- Guilt or shame framing ("you missed 4 days").
- Feeds that spotlight inactive friends.
- Many descriptive charts with no action.
- Totals that only ever go up, unrelated to any goal.
- Justifying a recap as a retention feature.

Not verified: Todoist Karma, Oura/Whoop insights, Apple ring outcomes, and notification fatigue numbers. Treat any claims about those as unverified.

### Kindred's own data and history

**History:** the analytics feature went through a large phased build-out on mobile:
- Phase 1: widget dashboard
- Phase 2: drilldowns for category, workspace, insight and habits
- Phase 3: kudos effect, support coverage, weekly review, friend view
- Phase 4: server-synced layout and "add cards"

**It was then hidden on both platforms.** The mobile Activity tab is hidden ("hidden for now"), and Activity was removed from the desktop sidebar. The page reached about 15 widgets and then lost its place in navigation.

**A design spec already exists** (`docs/superpowers/specs/2026-06-12-analytics-page-design.md`, draft) and it is still not built:
- **Intent:** a "personalized insight engine." A narrative lead card shows the #1-ranked insight with action buttons, and "two users see materially different pages."
- **Deliberate cuts in that spec:**
  - No composite score as the headline (citing Kluger & DeNisi).
  - No leaderboards (citing Hanus & Fox).
  - No unbroken-chain framing: **the word "streak" never appears in copy** (use "run", "consistent", "X weeks in").
  - No charts below a minimum sample size.
- **Not built:** the ranked engine and the lead card. Only the kudos-effect comparison enforces a minimum sample (at least 3 tasks with kudos and 3 without).

**Takeaways are fixed templates, not ranked or personalized.** Exact copy:
- Progress: "%s carried the %s: %d done, mostly %s." / "%s carried the %s with %d done."
- Share: "%s led this period at %d%%." / "Your focus was spread across several categories."
- Heatmap: "Most active on %s."
- Best time: "Your peak time is %s around %s."
- Habits: "%s is your strongest rhythm. %s needs a reset."
- Support: "%d%% of your finished work had someone in your corner." / "Only %d%% of your work had support — tag a friend to bring them along."
- Kudos effect: "Tasks with Kudos tended to finish faster." / "…took a little longer this period — support isn't only about speed." / "…about the same pace…"
- Each has a "not enough data yet" variant.

**Known bug:** analytics compute everything in **UTC**, not the user's timezone. Day buckets, week starts, and the best-time grid are shifted for anyone outside UTC. Rings and the For You feed do use the user's timezone.

**Related systems that already exist:**
- **For You feed:** cards for kudos received, ring progress ("%d tasks until you close today's ring"), comment replies, friend requests, and a **weekly recap** ("%d kudos received · %d sent · %d comments · %d ring closures"). The recap uses a rolling 7 days and counts only. The feed records views and dismissals per card.
- **Personalization memory** (`user_memory`): stated preferences such as planning style, tone, nudge frequency and peak hours. Stated values override inferred ones. They feed AI prompts, but analytics doesn't use them.
- **Rings:** daily targets Plan 2 / Do 3 / Share 1 in the user's timezone, a 7-day productivity score, ring history, and a notification to friends when all rings close.
- **End-of-day review:** a spec for an evening (8pm to midnight) card to bulk check off tasks and quick-log the day.

**Collected but unused for insights:**
- Actual focus time (`workingOnSince`, `timeTaken`).
- `startTime`, on-time/late flags, snooze/someday/release behaviour.
- Ring history beyond 7 days.
- Stated peak hours.
- Kudos reactions and media type, comments, posts.
- Calendar events (synced, but never correlated with completions).
- **Gaps:** tasks have no time estimates, so there's no estimate-vs-actual signal. The desktop app sends no product analytics events. Mobile sends a rich PostHog event set (task lifecycle, plan built or snoozed, kudos viewed, return after a gap, and so on).

### Patterns from strong apps (Mobbin)

Based on screens actually seen. Not found on Mobbin: Strava Year in Sport, Whoop, Todoist/Things/Sunsama reviews, Finch, Habitica.

**Recaps:**
- **Duolingo Year in Review** ([flow](https://mobbin.com/flows/c9b06caa-92f5-433f-8ed5-5660b8cff004)): opens from a teaser bottom sheet, then 10–11 full-screen cards, each with one highlighted number plus a playful line ("**566 days** was your longest streak. Okay, hot stuff!"). Every card has its own Share button.
- **Duolingo share poster** ([flow](https://mobbin.com/flows/8571a01f-da27-4bd6-a43b-e6b59ebadcd6)): the ending is a first-person poster ("I'm a top 8% learner") with a 2×2 stat grid and a "Share for a reward" button.
- **Spotify Wrapped** ([flow](https://mobbin.com/flows/12ddff8c-766e-4762-bceb-6edd93ba57a2)): Instagram-style stories with a progress bar. Each big number gets a percentile ("top 15% of listeners worldwide"), and teaser cards come before each reveal. Ends on a summary poster plus "Replay".
- **Weekly report:** Oura ([screen](https://mobbin.com/screens/90ebee77-8190-44c5-95cf-8904ec501a49)) reads like a short article: a sentence first ("Your average Activity Score for last week was 90"), the chart second, and a threshold that explains what "good" means.
- **Best and worst day:** Opal ([screen](https://mobbin.com/screens/ea59c327-1787-47dc-b850-15708c5e337d)) frames the chart with "Your most productive day was **Friday**…"
- **Improvement list:** Lifesum ([screen](https://mobbin.com/screens/995c8574-0cd0-445b-871e-f8e1704b8f84)) leads with "Two ways to improve your score", each with an action.
- **Against your own baseline:** Strava ([screen](https://mobbin.com/screens/fff0b506-9862-44e7-80a9-e1e447d404d9)) compares this week to your own 3-week average, not an absolute target.

**"We noticed" insight cards:**
- **Insight turned into a plan:** Fitbit/Google Health coach ([screen](https://mobbin.com/screens/11294425-4d03-4375-9bcf-55da80b226e5)): "Let's start the week with your 6:00 AM strength habit… The win is just showing up." The user accepts with one-tap replies like "I'm in for 6:00 AM".
- **Reflective, guilt-free framing:** Oura Advisor ([screen](https://mobbin.com/screens/22f7020c-3c39-48fc-9e8c-c64cd071f1b4)) treats rest as legitimate and asks a question instead of passing a verdict. Its weakness is long blocks of AI text.
- **Celebrate first, detail on demand:** Strava Athlete Intelligence ([screen](https://mobbin.com/screens/f6b18597-ed12-4014-98bb-7da449d3ad85)) leads with praise and offers a "Say More" button.
- **Feedback on insights:** Garmin ([screen](https://mobbin.com/screens/6bd9841f-3d1e-4e83-b4c4-6a8ba8937f83)) lets users rate each insight as Interesting or Not interesting.
- **Honest about missing data:** MacroFactor ([screen](https://mobbin.com/screens/5a434e04-c693-4881-8ec3-84cf24f60d44)) labels insights it can't compute yet as "Waiting".

**Social:**
- **Closest analog to kudos:** Future Pro ([screen](https://mobbin.com/screens/4e336fac-48a9-4d27-ae90-2b4cd96e875c)): "Let your friends pull you forward," with "Courtney M. cheered for your workout" and a Nudge button.
- **No app** showed "who supports you most" or "encouragement made you faster." Kindred's kudos-effect and top-supporters data looks novel.

**Recurring principles:**
1. The sentence leads; the chart is evidence.
2. Every number gets context: your own past, a percentile, or a threshold.
3. Warm voice; weak spots framed as "ways to improve", never failure.
4. One idea per card; at most two improvement items.
5. Each insight gets exactly one action.
6. The share artifact is first-person and identity-framed.
7. Teasers build anticipation before reveals.
8. Be honest when there isn't enough data, and let users rate insights.

**Pacing:**
- **Daily:** short cards with an action.
- **Weekly:** a short story or article with comparisons and one or two coaching points.
- **Yearly:** a 10–15 card celebration that ends in a shareable poster. Yearly recaps celebrate; weekly recaps coach.

**Anti-patterns seen:** KPI-tile dashboards with no interpretation (Toggl, Fitbit steps); long, equally weighted status lists; clinical red "Off-track" labels; peer comparison that shames; social screens that are just empty states pushing invites.

## 9. Synthesis: where the three tracks agree

1. **Kill the dashboard as the main surface.** Evidence (people abandon data they can't act on), the patterns (every strong example leads with a sentence), and Kindred's own history (about 15 widgets were built, then hidden on both platforms) all point the same way. The existing draft spec already called for a ranked "lead insight" with actions. It was never built.
2. **Lead with one ranked insight plus one action.** The strongest-evidence candidates:
   - Your week vs your own recent average.
   - Habit runs, worded per the spec as "run" or "X weeks in", never "streak", with a way to recover.
   - Stalled tasks with a one-tap next step.
3. **Weekly is the core rhythm.** A short weekly story that coaches, built on the existing For You weekly recap, which today is counts only. A yearly recap is for celebration and sharing, not retention.
4. **Social is the differentiator, framed carefully:**
   - Sharing progress beats private tracking.
   - Light, friendly comparison with friends beats encouragement alone.
   - Never spotlight inactive friends.
   - "Who showed up for you" and the kudos effect appear in no other app. Word the kudos effect as a correlation.
5. **Demote or cut descriptive views:** category share, health scores and status labels, the 6-month range, and the best-time grid. The best-time grid could instead quietly power defaults, like home ordering and suggested times.
6. **Fix the foundations first:**
   - Analytics compute in UTC, so day and hour insights are wrong for most users.
   - Only one minimum-sample gate exists.
   - Desktop sends no product events, so there's no way to measure whether any of this works.

**Implication for the current desktop Activity redesign:** the Overview / Patterns / Together views are an improvement but still a dashboard. The Patterns view in particular is mostly the weakly supported material.
